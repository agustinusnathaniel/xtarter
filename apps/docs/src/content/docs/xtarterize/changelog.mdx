Latest updates and feature releases for xtarterize.

## v1.25.0 — 2026-08-12

### Fixed

- `add` now honors `--include-conflicts` like `init`/`sync`: `add --all` and `add <task-id>` can force-apply tasks whose configuration conflicts, and `add --all` warns when conflicting tasks were skipped so CI runs aren't silently incomplete.

## v1.24.0 — 2026-08-11

### Fixed

- `add` no longer claims a conflicting task "applied successfully": when a task conflicts with existing configuration (e.g. `ts/strict` on a tsconfig that already sets `strict: false`), `add` now reports it as not applied, exits 1, and leaves the conflicting file untouched. Interactive mode counts conflicts as skipped instead of applied, and `diff` now shows conflict diffs.
- `sync` and `init` now honor `--include-conflicts` in non-interactive (`--yes`/quiet) mode: the flag was previously passed through in the interactive paths but silently dropped for `--yes`, so conflicting tasks were skipped even when the flag was set — exactly the automation scenario where it matters.

## v1.23.0 — 2026-08-10

### Fixed

- `undo` now removes files that the last run created (like `biome.json` or `tsconfig.json`) instead of failing with "No backup found" — the working tree is fully restored to its pre-run state.

## v1.22.0 — 2026-08-10

### Fixed

- `check --badge` no longer corrupts machine-readable output: `--badge - --json` keeps stdout as pure JSON (the SVG goes to stderr), `--badge <file> --json` suppresses the "Badge written" success message from stdout, and `--badge -` in human mode keeps stdout as a clean SVG by routing the audit report to stderr.

## v1.21.0 — 2026-08-10

### Added

- `check` now emits GitHub Actions workflow command annotations (`::error` / `::warning`) for non-conformant tasks and failing diagnostics — one annotation per task, linked to the config file it would modify. Use `--annotations` to force it, or it auto-enables inside GitHub Actions. Conformance failures now appear inline on the PR, not just as an exit code.

## v1.20.0 — 2026-08-04

### Added

- CI-friendly exit codes: `check` exits 1 when the project has pending changes or failing diagnostics, `diff` exits 1 when at least one change is pending (mirroring `git diff --exit-code`), and `doctor` exits 1 when at least one diagnostic fails. `init`/`sync --dry-run` and other mutating commands also exit 1 on dry-run task failures. This makes `xtarterize` usable as a CI gate — pipelines can now fail builds on non-conformant projects.

## v1.19.0 — 2026-07-21

### Added

- New `quality/package-engines` task: records Node >=24 and your project's package manager version in `package.json`, so tools know what runtime you expect
- New `workspace/pnpm-workspace` task: generates `pnpm-workspace.yaml` for pnpm projects — monorepos get the standard package layout, single-package projects get a minimal placeholder
- New `release/versionrc` task: generates `.versionrc.json` so commit-and-tag-version only includes meaningful change types in your changelog

### Changed

- `ts/strict` now enforces `noUnusedLocals`, `noUnusedParameters`, and `verbatimModuleSyntax` alongside `strict: true` — catches dead code and ensures proper type imports
- `release/git-hooks` adds a `prepare-commit-msg` hook: if you use czg or commitizen, commits will prompt you interactively
- `editor/vscode`: format on paste is now off by default, generated TanStack Router files are hidden from the explorer, and TypeScript acquisition is better configured
- CI workflow templates now default to Node 22 instead of 20

### Fixed

- `workspace/pnpm-workspace` no longer ignores changes to an existing workspace file
- `quality/package-engines` now respects your project's actual package manager instead of always assuming pnpm

## v1.18.0 — 2026-07-06

- New `mergeYaml` / `parseYaml` functions in `@xtarterize/patchers` for deep-merging configuration into YAML files. Existing keys are preserved, incoming keys fill gaps. Works with GitHub Actions workflows, Renovate configs, and any YAML-based config file.
- Plugin specifier validation `(ADR 026)`: Plugin specifiers in `.xtarterizerc` and `package.json` `xtarterize.plugins` are now validated as npm package names. Relative paths (`../../malicious.js`), absolute paths (`/etc/passwd`), and URL specifiers are rejected — preventing arbitrary code execution from attacker-controlled paths.
- `installDependency` now throws an error when installation fails, instead of silently logging a warning and continuing.
- Backup source path traversal protection: restored files from `xtarterize undo` are now validated to resolve within the backup directory.

## v1.17.0 — 2026-07-01

- The `.xtarterize/` directory (backups, cache) is now automatically added to `.gitignore` when running any `xtarterize` command. No more untracked files in `git status`. (ADR 026)

## v1.16.0 - June 29, 2026

### Natural language task query

New `xtarterize query <query>` command that discovers tasks using a pure-algorithmic scoring engine (no AI). Five weighted signals (label, id, group, keywords, config) with Levenshtein fuzzy matching, domain-specific synonym expansion, and coverage-based ranking.

Results are grouped by domain bundle (e.g. TypeScript, CI/CD) with per-group actionable `xtarterize add` commands.

New `xtarterize init --compose <query>` flag that reorders init tasks by relevance.

### Task metadata enrichment

New optional `searchMeta` field on the Task interface (`tags`, `configTargets`, `keywords`) enables richer search. All 26 built-in tasks include search metadata.

## v1.15.2 - June 29, 2026

### Monorepo-aware task filtering

Running `xtarterize` in a monorepo now shows only relevant tasks for where you're running from:

- Running from the monorepo root? You'll see CI/CD, release tooling, turbo, renovate, and editor config tasks - not package-level tsconfig or Vite plugin tasks.
- Running inside a workspace package? You'll see tsconfig path aliases, `vite-plugin-checker`, and `rollup-plugin-visualizer` - not root-level CI or release tasks.
- Tasks that apply everywhere continue to work as before.

Also fixes a detection bug where Node.js projects using Vite for build orchestration were misidentified as `runtime: 'browser'` instead of `runtime: 'node'`.

### Concurrency and CI resilience

Running `xtarterize` concurrently across multiple workspace packages no longer crashes with spurious file-not-found errors thanks to cache collision protection. Tests are also now more resilient to transient failures and version drift in external tools.

## v1.15.0 - June 29, 2026

### Restore, add, and doctor flags

New flags across the restoration, add, and diagnostic commands: `restore --yes` skips confirmation when restoring the latest backup, while `restore --quiet` suppresses verbose output. `add --all` applies all new and patch tasks without interaction, and `doctor --json` is now visible in command-level `--help`.

### create-xtarter-app scaffolding enhancements

`create-xtarter-app` gains several new flags: `--quiet` suppresses banners and progress output, `--json` outputs the scaffold result as structured JSON, and `--no-color` disables colorized output. The `--yes` flag now defaults to the `next-chakra` template when `-t` is omitted. The help system has been migrated from hand-rolled `HELP_TEXT` to citty auto-generated help.

### Documentation updates

CLI reference documentation in Starlight now covers the new flags, agent skills have been updated for accurate flag references, and JSON output examples have been corrected to match the actual output shape.

## v1.14.3 - June 29, 2026

### Multi-package-manager git hooks

Git hooks generated by `xtarterize add release/git-hooks` now work across npm, yarn, and bun, using the correct command format for each package manager via `nypm`.

### Engine and safety hardening

The minimum Node.js version has been raised to 24 - projects using Node 18–23 now receive a clear error from npm instead of a cryptic runtime failure. Backup collision resolution ensures files with names that could collide in the backup directory (e.g., `a/b.js` and `a__b.js`) use a collision-safe encoding scheme. `xtarterize undo` and `xtarterize restore` now reject restore operations targeting files outside the project root via path traversal protection.

### Detection and dry-run accuracy

Vite plugin dry-run output for tasks like `vite-plugin-checker` and `rollup-plugin-visualizer` now matches what `xtarterize add` actually writes. The detection cache has been improved so config directory changes (`.github/`, `.vscode/`, `.changeset/`) are tracked at the file level, ensuring stale project profiles are invalidated when files within these directories change.

## v1.14.2 - June 17, 2026

Edge-case hardening across the entire pipeline - no new features, but significantly improved stability for all commands and surfaces.

### CLI resilience improvements

try/catch guards prevent crashes on individual task failures across `init`, `sync`, `diff`, `add`, `doctor`, and `restore`. The `--skip`/`--only` flags no longer filter phantom empty-string values, and `doctor` uses `Promise.allSettled` for resilient diagnostics when one check fails.

### Core stability hardening

Robust error handling for atomic writes with temp file cleanup ensures no orphaned temp files. Schema validation guards against corrupted cache entries. Fixed a React Native + React co-detection issue that returned `null`. The skipped count now correctly tracks explicit skips from the check phase.

### Task reliability fixes

Fixed `this.getScripts` undefined crash in `packageScriptsTask`. The `commitMsgHook` now accepts a package manager parameter instead of hardcoding pnpm. Corrected `check()` return values for proper `conflict` vs `new` status detection.

### UI and JSON output fixes

The merged multi-diff view now preserves all diffs instead of dropping earlier ones. The JSON `ok` field reflects actual conformance state, not intention. Multiselect cancel properly aborts via `abortIfCancelled`.

### create-xtarter-app cross-platform fixes

Windows-compatible path handling, fixed pnpm overrides crash, async `readdir` replaces sync `readdirSync`, improved project name sanitization, and proper handling of explicit `false` CLI flag values.

### Documentation corrections

Outdated content refreshed - Node.js minimum bumped to 24, missing `--timing` and `--format` flags documented, Rspack added to detected bundlers, task applicability fixed for renovate/lint-staged, and CLI path corrected from `apps/cli` to `apps/xtarterize`.

## v1.14 - May 29, 2026

### Undo command

<Aside type="note" title="New `undo` command">
  `xtarterize undo` reverts the last run by restoring all backed-up files in one command - no need to manually cherry-pick individual file restores.
</Aside>

### Interactive add and conformance badges

`xtarterize add` without a task ID now shows a grouped multi-select menu for interactive task selection. `xtarterize check --badge <path>` generates an SVG conformance badge with score, progress bar, and status.

### Task cleanup and framework gating

Removed `editorconfig`, `nvmrc`, and `agent/skills` tasks - editorconfig is redundant with linters and VS Code settings, nvmrc `lts/*` is too vague, and agent/skills duplicated AGENTS.md content. The `codegen/plop` task now requires a detected framework to be applicable.

## v1.13 - May 17, 2026

### Oxlint and Oxfmt support

<Aside type="note" title="Oxlint & Oxfmt support">
  When Vite+ is detected, xtarterize now configures oxlint/oxfmt (via `vp`) instead of Biome as the default linting/formatting stack. Generates `oxlint.config.ts` / `oxfmt.config.ts` (or `.oxlintrc.json` / `.oxfmtrc.json` for existing configs), extends Ultracite presets, and uses a single `vp check` CI step.
</Aside>

### Enhanced lint rule coverage

Non-recommended lint rules are now mapped from ESLint configs: `eqeqeq`, `prefer-const`, `no-shadow`, `max-params`, React rules, and Vitest overrides for Oxlint; `noExcessiveCognitiveComplexity` and `useMaxParams` for Biome.

### TypeScript config templates

Generated config templates for Biome, Oxlint, Oxfmt, and commitlint now ship with proper TypeScript types.

## v1.12 - May 15, 2026

### Node.js 24 minimum requirement

The minimum Node.js version has been bumped to 24. Older versions receive a clear error from npm instead of a cryptic runtime failure.

## v1.11 - May 13, 2026

### Per-task progress indicators

Each task during `init` and `sync` now shows a spinner animation at the task level, giving you real-time feedback on what's being applied. The conformance plan table uses colored status tags (`new`, `patch`, `skip`, `conflict`) for at-a-glance understanding.

### Monorepo dependency management

The workspace flag (`-w`) is now supported for pnpm dependency installs in monorepo roots, making it easier to manage shared dependencies alongside per-package installs.

## v1.6 - May 11, 2026

### JSONC preservation

<Aside type="note" title="JSONC preservation">

Duplicate scripts with the same command are now skipped automatically during package script management. The `"extends": "config:base"` format is treated as equivalent to `"extends": ["config:base"]`, and only missing scripts are added - existing scripts are never overwritten.
