xtarterize scans JavaScript and TypeScript projects, selects the conformance tasks that apply, previews the changes, and applies approved updates. Coverage is deepest for Vite, React, and TypeScript projects.

:::caution[Experimental stacks]
Other stacks such as Vue, Svelte, Solid, Node CLIs, and Bun work but stay experimental with fewer tasks.
:::

## What a run changes

xtarterize writes configuration, not application code. A run can add or update linter and formatter configs, `tsconfig.json` strictness and path aliases, GitHub Actions workflows, editor settings, release tooling, and agent instructions. Your source files, dependencies, and scripts you wrote yourself are never touched.

## What it will not do

- **Overwrite your values.** A config key you set deliberately is preserved; xtarterize only fills gaps (see [configuration](/xtarterize/guide/config/overview/)).
- **Hide a conflict.** Incompatible values are reported for your decision instead of being silently replaced.
- **Leave you stuck.** Every modified file is backed up under `.xtarterize/`, and `undo` reverts a whole run or `restore` brings back one file.
- **Waste a run.** Tasks are idempotent: a second run makes no changes.

## How a run works

Every run follows five steps: detect, resolve, check, plan, apply. See [How a run works](/xtarterize/#how-it-works) for what each step does.

## Which command when

| Command | Reach for it when |
| --- | --- |
| `init` | First conformance pass on a project |
| `sync` | Templates have moved on and you want the updates |
| `check` | Auditing conformance, or gating CI |
| `diff` | Reviewing pending changes before applying |
| `add <task-id>` | Applying one specific task |
| `query "<words>"` | Finding the right task by description |

Full flags and exit codes live in the [CLI reference](/xtarterize/guide/cli/overview/).
