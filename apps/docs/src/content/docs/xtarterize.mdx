<p class="xt-eyebrow xt-section-label">01 · The pipeline</p>

<h2 class="xt-section-title">How it works</h2>

<p class="xt-section-lead">Every xtarterize run follows the same five steps - from reading your project to applying changes with backups in place.</p>

<ol class="xt-steps xt-rise">
  <li class="xt-step">
    <span class="xt-step-num">01</span>
    <h3 class="xt-step-name">Detect</h3>
    <p class="xt-step-desc">Scans your project to build a full profile: framework, bundler, styling, package manager, monorepo status, and existing configs.</p>
  </li>
  <li class="xt-step">
    <span class="xt-step-num">02</span>
    <h3 class="xt-step-name">Resolve</h3>
    <p class="xt-step-desc">Maps the profile to the conformance tasks that apply - Vite tasks only for Vite projects, never a generic one-size-fits-all set.</p>
  </li>
  <li class="xt-step">
    <span class="xt-step-num">03</span>
    <h3 class="xt-step-name">Check</h3>
    <p class="xt-step-desc">Determines each task's status: new (file missing), patch (needs merging), skip (already conformant), or conflict (incompatible).</p>
  </li>
  <li class="xt-step">
    <span class="xt-step-num">04</span>
    <h3 class="xt-step-name">Plan</h3>
    <p class="xt-step-desc">Displays a conformance plan table for review, so you see exactly what would change before anything is written.</p>
  </li>
  <li class="xt-step">
    <span class="xt-step-num">05</span>
    <h3 class="xt-step-name">Apply</h3>
    <p class="xt-step-desc">Backs up your files, then applies changes with deep merge or AST manipulation - leaving your originals restorable.</p>
  </li>
</ol>

<Aside type="caution" title="Current focus: Vite + React + TypeScript">
  The CLI detects a wide range of frameworks, but the deepest task coverage is for **Vite**, **React**, and **TypeScript** projects. Support for other stacks (Vue, Svelte, Solid, Node CLI, Bun, etc.) works but is **experimental** - tasks may be fewer or less mature. Contributions to expand coverage are welcome.
</Aside>

<p class="xt-eyebrow xt-section-label">02 · Safety rails</p>

<h2 class="xt-section-title">Guardrails by design</h2>

<p class="xt-section-lead">Conformance automation is only useful if you trust it. These guarantees hold on every run.</p>

<div class="xt-guardrails xt-rise">
  <div class="xt-guardrail">
    <span class="xt-guardrail-kicker">Safe</span>
    <h3>Never destructive</h3>
    <p>Shows you a diff before any change. Backs up your files. You're always in control.</p>
  </div>
  <div class="xt-guardrail">
    <span class="xt-guardrail-kicker">Idempotent</span>
    <h3>Safe to rerun</h3>
    <p>Idempotent by design. Run it ten times - no duplicates, no corruption, no drift.</p>
  </div>
  <div class="xt-guardrail">
    <span class="xt-guardrail-kicker">Selective</span>
    <h3>Applies only what fits</h3>
    <p>Only suggests configs that match your detected tooling and project structure.</p>
  </div>
  <div class="xt-guardrail">
    <span class="xt-guardrail-kicker">Context-aware</span>
    <h3>Detects your stack</h3>
    <p>Scans your project to understand what frameworks, tools, and configs you're using - before touching anything.</p>
  </div>
</div>

<p class="xt-eyebrow xt-section-label">03 · Quick start</p>

<h2 class="xt-section-title">Quick Start</h2>

Get up and running in under a minute:

```bash
# 1. Initialize conformance for your project
npx xtarterize init

# 2. Check your current conformance status
npx xtarterize check

# 3. Preview what changes sync would make
npx xtarterize diff
```
